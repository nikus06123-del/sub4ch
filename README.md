# Sub4ch Checker v2.3

Программа собирает бесплатные VPN-конфиги из **85+ проверенных подписок** (плюс само-растущий пул источников), проверяет каждый сервер **двумя ступенями** — как это делает сам Throne — и публикует живые в вашу подписку на GitHub **каждые 2 часа**.

Подписка совместима с Throne и любыми клиентами на Xray / sing-box: v2rayN, Nekoray, Hiddify, Streisand и т.д.

## Что нового в v2.3 — ВСЕ конфиги за 5–10 минут

- **Пакетная проверка ядром (главное).** Раньше на каждый конфиг запускался отдельный процесс Xray/sing-box — 100–300 процессов одновременно, таймаут до 10 секунд, поэтому полный список из ~150 тыс. конфигов проверялся около часа. Теперь **одно ядро проверяет сразу 200 конфигов**: у каждого свой локальный порт, ядро направляет трафик каждого порта через свой сервер. 6 ядер = 1200 проверок одновременно при потреблении ОЗУ меньше 1 ГБ. Ступень 2 ускорилась на порядок.
- **Полный прогон — режим по умолчанию.** `run_checker.bat` больше не режет список до 30 тыс.: проверяются **ВСЕ** конфиги, типичное время — **5–10 минут** на гигабитном канале (было ~1 час). Для быстрого освежения подписки остался `run_checker_fast.bat` (выборка 10 тыс., 2–4 минуты).
- **TCP-фильтр без «ступенек»:** новое соединение стартует сразу, как только освободился слот (раньше чанки по 500 ждали друг друга); соединение к одному адресу делается **один раз** на все конфиги этого адреса; DNS-резолв параллелится на 256 потоков.
- **Порты больше не кончаются:** локальные порты возвращаются в пул после теста (раньше после ~25 тыс. проверок в длинном цикле могли начаться сбои).
- **Автоматический откат:** если ядро отклоняет пачку (кривой конфиг, антивирус), она проверяется по-одиночке — результат не теряется; после 5 неудач программа сама возвращается на старую схему.
- Тонкая настройка: `CHECKER_BATCH` (0 — старая схема), `CHECKER_BATCH_SIZE`, `CHECKER_BATCH_PARALLEL`, `CHECKER_DNS_WORKERS`.

## Что нового в v2.2

- **Отдельная мобильная подписка.** Вместе с основной программа публикует `sub_mobile.txt` — **топ-200 самых быстрых серверов**. Файл в 15 раз меньше основной подписки: телефон качает его за секунды и не тормозит при переключении серверов. Лимит настраивается (`mobile_limit` в config.ini или `CHECKER_MOBILE_LIMIT`).
- **Скрипты для мобильного интернета:** `run_checker_mobile.bat` (ПК через точку доступа телефона) и `run_checker_mobile.sh` (прямо на Android в Termux) — с щадящими лимитами трафика и потоков.
- **deploy_github.py — деплой в один клик.** Одна команда `python deploy_github.py` публикует программу в репозиторий и включает автопилот GitHub Actions. Git и ручная загрузка файлов больше не нужны.
- **Проверено живым прогоном:** 168 тыс. URI из источников -> 91 тыс. уникальных конфигов -> 129 живых из 300 проверенных за 51 секунду (включая скачивание ядер).
- **Понятная диагностика токена:** если у fine-grained токена нет права записи (HTTP 403 «Resource not accessible by personal access token»), программа печатает пошаговую инструкцию, как включить "Contents: Read and write".
- **Повторы публикации:** сетевые сбои и конфликт версий файла (409/429/5xx) ретраятся автоматически — подписка публикуется надёжнее.
- Токен больше не может случайно утечь в репозиторий: `config.ini` добавлен в `.gitignore`.

## Что было нового в v2.0

- **Полная автономность (главное).** Программа теперь умеет работать вообще **без вашего компьютера** — на бесплатных серверах GitHub Actions по расписанию каждые 2 часа. ПК выключен — подписка всё равно обновляется. Токен не нужен: GitHub сам выдаёт встроенный.
- **Источников стало 85+** (было 16). Добавлены мега-агрегаторы (FastNodes, Mineral, SoliSpirit, TGParse, OpenRay, FreeNodes...), RU-специфичные списки и внешние агрегаторы. Все URL проверены живыми запросами при сборке.
- **Поддержка формата Clash YAML** (миллионы конфигов лежат именно в нём): анаэр, ermaozi, mahdibland, NoMoreWalls, AutoMergePublicNodes и другие.
- **Динамические источники:** каждый цикл программа берёт случайную выборку из поддерживаемого сообществом каталога подписок (1153+ ссылок из 112 репозиториев) — пул источников растёт сам, без обновления программы.
- **stats.json** — в репозитории публикуется статистика каждого цикла: сколько источников скачалось, сколько проверено, сколько живо.
- **Устойчивость:** лимит потоков ОС, падение части источников и «полуживые» прокси больше не ломают цикл; HTTP-ответ через туннель (не 204) теперь тоже считается «сервер жив».

## Два режима работы

| | Режим А — GitHub Actions (автономный) | Режим Б — на своём ПК |
|---|---|---|
| Компьютер должен работать | **Нет** | Да (открытое окно или планировщик) |
| Настройка | ~10 минут, один раз | ~10 минут, один раз |
| Токен GitHub | **Не нужен** | Нужен Personal Access Token |
| Стоимость | Бесплатно (публичный репозиторий) | Бесплатно |
| Проверка «как из России» | Нет — серверы GitHub за рубежом | Да — проверка вашим провайдером |

Рекомендация: включите **оба** режима не обязательно — выберите А, если нужен просто работающий автосборщик; выберите Б, если важно отбирать серверы, живые именно у вашего провайдера.

## ⚠️ GitHub Actions отключены

Файл `.github/workflows/update.yml` **удалён из репозитория** — автопрогоны на серверах GitHub больше не выполняются. Подписка в репозитории обновляется **только когда вы запускаете проверку сами**:

- на ПК: `run_checker.bat` (или `python checker.py --loop` — каждые 2 часа, пока открыто окно);
- в Termux: `bash run_checker_mobile.sh`.

Бесплатные серверы умирают быстро — без периодических проверок список «протухает» за день-два, поэтому запускайте проверку хотя бы раз в день.

Вернуть автопилот просто: загрузите файл `update.yml` обратно в `.github/workflows/` репозитория (или скажите мне — верну за минуту).

## Режим А. Полная автономность на GitHub Actions (без ПК) — сейчас отключён

1. Создайте/убедитесь, что существует **публичный** репозиторий `nikus06123-del/sub4ch` (Settings → **Change visibility** → Public, если приватный).
2. Убедитесь, что токену выдано право записи: **Contents: Read and write** (см. раздел «Режим Б», шаг 3).
3. В распакованной папке выполните:
   ```
   python deploy_github.py
   ```
   Скрипт сам загрузит все файлы программы в репозиторий (Git не нужен) и подскажет дальнейшие шаги.

   Альтернатива без скрипта — вручную через веб: **Add file → Upload files**, а папку `.github/workflows/update.yml` создать через **Create new file** (имя `.github/workflows/update.yml`, содержимое — из этой папки).
4. Откройте вкладку **Actions** в репозитории. Если Actions отключён — нажмите кнопку включения («I understand my workflows, go ahead and enable them»).
5. Для первой проверки запустите вручную: **Actions → Update VPN subscription → Run workflow → Run workflow** (поле «Максимум конфигов» можно оставить 80000).
6. Через 20–60 минут в репозитории появятся `sub.txt`, `sub_plain.txt` и `stats.json`. Дальше всё обновляется само каждые 2 часа.

**Важно:** репозиторий должен быть публичным — на публичных репозиториях Actions бесплатны и без лимита минут, а Throne сможет читать подписку без авторизации. В репозиторий при деплое **не попадает** `config.ini` с вашим токеном — deploy-скрипт его исключает автоматически.

## Как это работает

```
sources.txt (85+ URL)  +  динамический пул (~60 случайных за цикл)
        |  скачивание: plain / base64 / Clash YAML — автоопределение
        v
Парсер vless / vmess / trojan / ss / hysteria2 / tuic  +  дедупликация
        |  лимит: не больше 20 конфигов на один IP:порт
        v
Ступень 1. TCP-фильтр (тысячи соединений одновременно, кеш на адрес)
        |  мёртвые IP/порты отсеяны
        v
Ступень 2. Проверка через ядра Xray и sing-box ПАЧКАМИ (v2.3):
        |  одно ядро держит ~200 локальных прокси-портов,
        |  каждый порт направляется через свой сервер;
        |  через сервер делается HTTP-запрос на 204-URL.
        |  Это та же проверка, что делает Throne: «порт открыт» ≠ «сервер работает».
        v
Сортировка по времени отклика -> sub.txt (base64) + sub_plain.txt + stats.json
        v
Публикация в GitHub (sub.txt, sub_plain.txt, stats.json) — с ПК или из Actions
```

Цикл повторяется каждые 2 часа (интервал настраивается). В подписку попадают **только серверы, через которые реально прошёл запрос**.

Ориентир по масштабу: за цикл сейчас скачивается ~350–400 тыс. строк конфигов, ~130 тыс. остаётся после дедупликации и лимита на адрес, живых — обычно 3–10 %.

## Режим Б. Запуск на своём ПК (Windows)

1. Установите Python 3.9+ с python.org — при установке отметьте **Add python.exe to PATH**.
2. Распакуйте папку `sub4ch-checker` в любое место, например `C:\sub4ch-checker`.
3. Создайте токен с правом записи, если его ещё нет:
   GitHub → Settings → Developer settings → **Personal access tokens → Fine-grained tokens** → Generate new token → Repository access: **Only select repositories** → `nikus06123-del/sub4ch` → Permissions → Repository permissions → **Contents: Read and write**.

   **Проверьте это внимательно** — токен без «Contents: Read and write» читает репозиторий, но публикация падает с ошибкой 403. Если токен уже создан: откройте его в списке, Permissions → Contents → **Read and write** → Save. Дополнительно полезно **Actions: Read and write** — право вручную запускать прогон из программы.
4. Вставьте токен в `config.ini` (строка `token =` в секции `[github]`).
5. Запустите `run_checker.bat` — первый цикл пойдёт сразу, дальше программа сама повторяет проверку каждые 2 часа, пока открыто окно.

Так как токен ранее проходил через чат в открытом виде, правильнее перевыпустить его (Fine-grained tokens → Regenerate) и вставить уже новое значение. В чат его больше не присылайте.

Для фона без открытого окна — Планировщик задач Windows: действие `python.exe C:\sub4ch-checker\checker.py`, расписание «Каждые 2 часа». Linux/cron: `0 */2 * * * cd /путь/sub4ch-checker && python3 checker.py >> checker.log 2>&1`.

## Проверка на мобильном интернете

Программа проверяет серверы **с того устройства и в той сети, где запущена**. GitHub Actions проверяет «из дата-центра в США», ПК с домашним Wi-Fi — «от домашнего провайдера». Чтобы отобрать серверы, живые именно на мобильном интернете (МТС, Мегафон, Билайн, Tele2 и т.д.), запускайте проверку, когда трафик идёт через мобильную сеть. Отдельной настройки «проверить для мобильного» не нужно — важна только сеть.

### Способ 1 — ПК через телефон (самый простой)

1. Включите на телефоне точку доступа (Wi-Fi-раздачу) или USB-модем. **Wi-Fi на телефоне выключите** — раздаваться должен именно мобильный интернет.
2. Подключите ПК к этой точке доступа, другие сети отключите.
3. Запустите `run_checker_mobile.bat` — обычная проверка с «мобильными» лимитами: 10 000 конфигов вместо всех (экономия трафика), 500 самых быстрых в подписку, сниженное число потоков.

### Способ 2 — прямо на Android через Termux

1. Установите Termux **с F-Droid** (версия из Google Play устарела): https://f-droid.org/packages/com.termux/
2. В Termux выполните:
   ```
   pkg update -y && pkg install -y git
   git clone https://github.com/nikus06123-del/sub4ch checker
   cd checker
   bash run_checker_mobile.sh
   ```
   Скрипт сам поставит Python с зависимостями, скачает ядра Xray/sing-box и запустит проверку с щадящими лимитами (6000 конфигов, 500 в подписку, 25 потоков — телефону хватает).
3. **Публикация в репозиторий:** перед запуском `export GITHUB_TOKEN=ваш_токен` (право Contents: Read and write) либо впишите токен в `config.ini`. **Без токена** проверка тоже работает: готовая подписка останется в `out/sub.txt` — её можно открыть в клиенте на том же телефоне как локальный файл.
4. Чтобы Android не убил проверку в фоне: Настройки → Батарея → Termux → «Без ограничений». Скрипт сам берёт wake-lock на время прогона.

iPhone/iPad не подходят — проверку на них не запустить, используйте способ 1.

### Трафик и расписание на мобильном

Один прогон с мобильными лимитами качает ориентировочно **100–200 МБ** (источники + выборка + тесты), полный прогон без лимита — от сотен МБ до 1 ГБ. Поэтому скрипты делают **один прогон** и выходят; запускайте их, когда удобно, или добавьте `--loop --interval 6` (каждые 6 часов) — но на тарифе с лимитом трафика лучше вручную.

### Особенности мобильной проверки

- Результат **отличается** и от Actions, и от домашнего Wi-Fi — это нормально: у операторов свой DPI и транзит. Именно это вы и измеряете.
- На мобильных сетях чаще всего не живут **hysteria2 и tuic** (UDP/QUIC операторы режут). Если они стабильно мёртвые — оставьте в `config.ini` → `[protocols] include` только `vless,vmess,trojan,ss`.
- Лучшие шансы у серверов на **порту 443** с транспортами ws / grpc / reality.
- Итог один: чей прогон опубликовался последним, тот и перезаписал `sub.txt`. Не смешивайте прогоны с Actions и с телефона, если для вас важен именно мобильный результат — см. ниже.

### Если результат с телефона должен быть главным

GitHub Actions по-прежнему обновляет подписку каждые 2 часа и перезапишет то, что вы опубликовали с телефона/ПК. Чтобы осталась только ваша проверка, отключите расписание: откройте на GitHub файл `.github/workflows/update.yml` → значок карандаша → удалите две строки

```yaml
  schedule:
    - cron: "0 */2 * * *"
```

→ Commit changes. Ручной запуск кнопкой (Run workflow) при этом сохранится.

## Альтернативы GitHub Actions (в том числе для РФ)

GitHub Actions остаётся основным режимом и работает из России. Если нужна независимость от GitHub — вот варианты по надёжности:

| Вариант | Цена | Автообновление | Комментарий |
|---|---|---|---|
| **VPS российского хостера** | ~130–300 ₽/мес | cron каждые 2 ч | **Лучший аналог Actions**: карта РФ, полная независимость, подписку можно раздавать прямо с VPS без GitHub. Хватит 1 CPU / 1–2 ГБ (Timeweb Cloud, Beget, Selectel, REG.RU, Yandex Cloud) |
| Свой ПК | 0 ₽ | run_checker.bat / Планировщик | Компьютер должен работать |
| Termux на Android | 0 ₽ | `--loop --interval 2` | Старый телефон как домашний сервер; см. «Проверка на мобильном интернете» |
| Hugging Face Spaces | 0 ₽ | cron внутри контейнера | Доступен из РФ без карты, но бесплатный Space может уснуть без запросов — нужно «будить» пингом |
| GitLab.com Schedules | 0 ₽ | по расписанию | Бесплатно всего 400 мин/мес — на проверку каждые 2 часа не хватит, только 1–2 прогона в день |
| Google Cloud / Oracle / AWS | — | — | Российские карты не принимают — не вариант |

### Установка на VPS одной командой

После создания VPS (Ubuntu 22.04+/Debian 12) подключитесь по SSH и выполните:

```
git clone https://github.com/nikus06123-del/sub4ch /opt/sub4ch-checker
cd /opt/sub4ch-checker && GITHUB_TOKEN=ваш_токен bash install_vps.sh
```

Скрипт поставит Python-окружение, настроит лимиты под слабый VPS, впишет токен, поставит cron «каждые 2 часа» и сразу запустит первый прогон.

Добавьте `--web` — тогда nginx будет раздавать подписку прямо с VPS, и Throne сможет читать её вообще без GitHub:

```
sudo bash install_vps.sh --web --no-github
```

Ссылки для Throne будут: `http://ВАШ_IP/sub.txt` и `http://ВАШ_IP/sub_mobile.txt` (мобильная, топ-200).

Ядра **Xray** и **sing-box** скачиваются автоматически при первом запуске в папку `bin\` — вручную ничего ставить не нужно.

## Настройка (`config.ini`)

Секция `[github]`:

| Параметр | Что делает |
|---|---|
| `token` | Personal Access Token — **только для локального режима**; в Actions не нужен |
| `repo` / `branch` | куда публиковать подписку |
| `path_base64` / `path_plain` / `path_stats` | имена файлов в репозитории |

Секция `[checker]`:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `interval_hours` | 2 | интервал циклов в режиме `--loop` |
| `max_configs_per_endpoint` | 20 | защита от списков с сотнями фейк-uuid на одном сервере |
| `max_results` | 0 | ограничить подписку N лучшими (0 — все живые) |
| `mobile_limit` | 0 | отдельная мобильная подписка: топ-N самых быстрых в `sub_mobile.txt` (в Actions включено значение 200) |
| `max_configs_per_run` | 0 | если уникальных конфигов больше N — проверять случайную выборку (0 — все; в Actions по умолчанию 80000) |

Секция `[sources]`:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `dynamic_url` | каталог сообщества | откуда брать динамический пул источников; пусто = отключить |
| `dynamic_max` | 60 | сколько динамических источников брать за цикл |

Секция `[testing]`:

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `tcp_concurrency` | 1000 | одновременные TCP-подключения ступени 1 (слабый ПК — 300–500) |
| `core_concurrency` | 100 | одновременные проверки через ядро, ~15–30 МБ ОЗУ на поток (4 ГБ ОЗУ — 50–70) |
| `core_timeout` | 10 | сек на тест одного сервера |
| `test_urls` | cloudflare/gstatic 204 | URL проверки выхода через сервер |
| `http_proxy` | пусто | прокси для GitHub, если он заблокирован провайдером (`socks5://127.0.0.1:2080` — локальный порт Throne) |

## Свои источники

Допишите URL в `sources.txt` — по одному в строке. Поддерживаются plain-списки, base64-подписки, Clash YAML и страницы `github.com/.../blob/...`. Нерабочие источники программа пропускает и пишет об этом в лог.

## Полезные команды

```
python checker.py                 один цикл проверки
python checker.py --loop          бесконечно, интервал из config.ini
python checker.py --no-push       проверить, но ничего не публиковать
python checker.py --limit 1000    отладка: проверить первые 1000 конфигов
python checker.py --no-core       только TCP-фильтр (быстро, но в подписку попадёт мусор)
python checker.py --cores-only    скачать/обновить ядра и выйти
CHECKER_MAX_RUN=30000 python checker.py    лимит конфигов на прогон (так делает Actions)
```

## Проблемы и решения

- **Actions не запускается по расписанию.** Расписание на GitHub сдвигается на 5–20 минут — это нормально. Проверьте: репозиторий публичный, файл лежит в `.github/workflows/`, Actions включены на вкладке Actions.
- **Ошибка «Resource not accessible by integration».** Значит у workflow нет прав на запись: в `update.yml` блок `permissions: contents: write` должен присутствовать (в готовом файле он есть).
- **Ошибка «Resource not accessible by personal access token» (HTTP 403).** У fine-grained токена нет права записи: Settings → Developer settings → Fine-grained tokens → ваш токен → Permissions → **Contents: Read and write** → Save. Менять сам токен не нужно. Программа при этой ошибке печатает ту же инструкцию в лог.
- **GitHub не открывается при локальном запуске.** Включите Throne и впишите в `config.ini`: `http_proxy = socks5://127.0.0.1:2080` (порт смотрите в настройках Throne).
- **Антивирус ругается на `bin\xray\xray.exe` или молча удаляет его.** Ложное срабатывание на открытый Xray. Программа теперь сама проверяет ядро запуском: если антивирус его испортил, она перекачает ядро и напечатает предупреждение. Чтобы ядро скачалось **один раз** и больше не трогалось — добавьте папку программы в исключения: Безопасность Windows → Защита от вирусов и угроз → Управление настройками → Исключения → Добавить папку.
- **В подписке мало серверов.** Смотрите `out/report.txt` / `stats.json`: TCP-фильтр отсеивает мёртвые адреса, ядро — невалидные uuid и заблокированные. 3–10 % живых от исходных — норма для бесплатных списков.
- **hysteria2/tuic все мёртвые.** UDP/QUIC может резать провайдер; уберите их в `config.ini` → `[protocols] include`.
- **Пустой результат цикла.** Программа **не затирает** старую подписку, если живых не нашлось ни одного — в репозитории остаётся прошлая версия.
- **Хочу, чтобы в репозитории была только подписка.** Просто не запускайте `deploy_github.py` — локальный режим публикует только `sub.txt` / `sub_plain.txt` / `stats.json`, сам код программы на GitHub не попадает. Если файлы программы уже загружены в репозиторий, удалите их через веб-интерфейс: откройте файл на GitHub → значок корзины → Commit changes.

## Примечания

- В режиме Actions проверка идёт с серверов GitHub (США): отбираются серверы, живые «из мира». Часть из них у российских провайдеров может не работать из-за DPI — это ограничение любого облака. Для отбора «как у вашего провайдера» используйте локальный режим.
- Конфиги на транспорте `xhttp` проверяются ядром Xray: в Throne для них должен быть выбран Xray-движок.
- Итоговая подписка отсортирована по времени отклика — самые быстрые серверы в начале списка.
- Программа проверяет только адреса из открытых подписок; никаких сторонних сканов не выполняется.
